# Project documentation continuity

This is a first database systems project. Use `PROJECT_GUIDE.md` as the beginner
entry point and living progress tracker; `README.md` contains technical setup.

When work changes the project's implementation, verification, scope or next stage,
update `PROJECT_GUIDE.md` in the same work: its update date, current position,
roadmap statuses, next steps and progress log as applicable. Explain new concepts
in plain language using this project's examples.

Keep planned, implemented and verified work distinct. Date verification claims
and link evidence; do not imply an old test was rerun today. Preserve dated
milestone reports as historical evidence. Documentation-only work must not mark
application functionality complete. Keep configuration secrets out of documentation.
